# Шаблон репозиторію лабораторних робіт «JavaScript Frameworks»

Стартова точка всіх чотирьох лабораторних робіт. У шаблоні налаштовано те,
що не є предметом курсу. Це складання двох реалізацій (React + TypeScript і
Svelte 5), суворий режим типізації, лінтинг, тести, спільний адаптер
контракту, детермінований генератор даних і контрольна команда. Усе, що
студент робить сам, у шаблоні лишено заготовками.

## Як почати

1. Створити власний репозиторій із цього шаблону на GitHub і клонувати його
   в короткий шлях поза текою хмарної синхронізації (у Windows, наприклад,
   `C:\jsf\prizvyshche`, перед клонуванням виконати
   `git config --global core.longpaths true`).
2. Встановити залежності командою `npm ci`.
3. Додати в `ATTRIBUTION.md` перший власний рядок про походження шаблону.
4. Запустити контрольну команду `npm run check`.

До кроку 3 контрольна команда закінчується рядком `НЕ ГОТОВО ✗ — тести`,
бо в `ATTRIBUTION.md` ще немає власного рядка студента. Після кроку 3
очікуваний вивід такий.

```
✓  середовище
✓  перевірка типів
✓  лінтинг
✓  складання
✓  тести
ГОТОВО ✓
```

Крок «середовище» перевіряє версію Node за полем `engines` найвимогливішої
залежності, наявність git, що проєкт є коренем репозиторію з віддаленим
`origin` на GitHub, і що тека не лежить у хмарній синхронізації. Якщо цей
крок червоний, решта кроків не запускається.

## Команди

| Команда | Що робить |
|---|---|
| `npm run check` | середовище, типи, лінтинг, складання, тести |
| `npm run ready -- 1` | повнота документів до захисту ЛР1, для наступних робіт номер 2, 3 або 4 |
| `npm run dev --workspace react-ts` | сервер розробки реалізації React (так само `svelte-5`) |
| `npm run size` | обсяг складання обох реалізацій у режимі випуску, запис у `measurements/bundle-size.csv` |
| `npm run journal -- 1` | перенести рядки CSV з `measurements/` у таблицю прогонів розділу 1 журналу і порахувати під нею медіану, мінімум, максимум і розкид (для інших робіт номер 2, 3 або 4) |
| `npm run diff` | перелік файлів двох реалізацій і кількість рядків різниці |
| `npm run data` | перегенерувати `data/data.json` із зерна `generator/seed.txt` |
| `npm run route -- variant-client /` | обсяг JavaScript маршруту зібраного варіанта Next.js (ЛР2) |
| `npm run find -- variant-server РЯДОК` | у яких файлах складання трапляється рядок (ЛР2) |
| `npm run tree` | скільки пакетів названо в маніфестах і скільки записів у файлі блокування (ЛР4) |
| `npm run lifecycle` | пакети, що виконують код під час встановлення, з `-- --check` звірка з `dependency-policy.json` (ЛР4) |
| `npm run sbom` | перелік складових CycloneDX у `check-reports/sbom.cdx.json` і його звірка з деревом залежностей (ЛР4) |
| `npm run attribution` | які прямі залежності не мають рядка в `ATTRIBUTION.md` і які рядки атрибуції не є пакетами (ЛР4) |
| `npm run lockfile -- "ПАКЕТ@ВЕРСІЯ"` | чи є пакети й версії з опису інциденту у файлах блокування проєкту і прогонника (ЛР4) |

## Що в проєкті

| Файл або тека | Роль |
|---|---|
| `DOMAIN.md` | паспорт предметної області (ЛР1) |
| `CONTRACT.md` | контракт компонента (ЛР1) |
| `JOURNAL.md` | журнал вимірювань усіх робіт |
| `ADR-000.md` | заповнений зразок запису архітектурного рішення |
| `ADR-001.md` … `ADR-004.md` | записи рішень ЛР1…ЛР4 |
| `ATTRIBUTION.md` | походження всього, що написав не студент |
| `dependency-policy.json` | машиночитна частина політики залежностей (ЛР4) |
| `data/` | набір даних, який складання копіює в застосунок |
| `generator/` | генератор (`index.mjs`), будова запису домену (`records.mjs`), зерно |
| `shared/` | типи й логіка домену, спільні для обох реалізацій |
| `contract/` | спільні випадки контракту і запити до сторінки за роллю та іменем |
| `react-ts/`, `svelte-5/` | дві реалізації з однаковим переліком файлів |
| `variant-client/`, `variant-server/` | два варіанти застосунку на Next.js для ЛР2, які беруть тип запису, фільтр і агрегат з `shared/data.ts`. До ЛР2 вони не входять у робочі простори, тому `npm ci` і `npm run check` їх не встановлюють і не складають |
| `tests/` | тести даних і документів |
| `tools/` | контрольна команда, готовність документів, вимірювання |
| `tools/runner/` | вимірювання затримки взаємодії (з ЛР1) і серії прогонів Lighthouse (ЛР2, ЛР3), окремий пакет, залежності якого встановлюються `npm ci` у цій теці |

Документи студента за весь курс такі: `README.md`, `DOMAIN.md`, `CONTRACT.md`,
`JOURNAL.md`, `ADR-001.md`…`ADR-004.md`, `ATTRIBUTION.md`. Розділи, яких
вимагає кожна робота, перевіряє `npm run ready`.
